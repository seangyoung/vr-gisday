# Spatial Discovery Lab — GIS Day

Quest-focused WebXR app with ten short experiences in one immersive selection gallery: **Find Yourself**, **Make It Rain**, **Scan the Hidden World**, **Stand Inside the Layers**, **Can You See It?**, **How Big Is a Pixel?**, **See the Invisible**, **Where Did the Cluster Go?**, **Make the World Flat**, and **What Changed?**. The four-column gallery curves gently toward the viewer; a controller ray and trigger open any demo directly.

## Run

Node 22 recommended.

```sh
npm ci
npm run dev
npm test
npm run build
```

Production: serve `dist/` over HTTPS. Quest cannot use ordinary HTTP from a laptop's LAN address for immersive WebXR. GitHub Pages supplies HTTPS. The ten demos need no runtime API keys or external asset requests; the separate recommended-video gallery loads YouTube thumbnails and embedded videos from YouTube when opened. Dependencies are bundled by Vite.

## Recommended Videos

The start page offers **Enter VR**, **Open room scan in MR**, and **Recommended Videos**. The last choice opens a browser gallery of five short AirPano 360° scenes: Everest, Bryce Canyon, Times Square, Dutch windmills, and Canaima Lagoon. Each card gives a geospatial observation prompt and opens a YouTube preview. **Open 360° video for immersive viewing** opens the publisher's YouTube watch page in a new tab. On Quest, visitors can use YouTube VR's immersive mode for a full 360° view; the headset decides whether that link opens Browser or the YouTube VR app. If it stays in Browser, the exact title is shown so the visitor can find the clip in YouTube VR. The app does not rehost or decode these streams in WebXR, and external playback requires network access. This handoff still needs validation on the target Quest headset.

A development-only `http://localhost:5173/?preview` view supports mouse selection of the same scene buttons for layout review. Optional `&stage=-2` (introduction), `&stage=-1` (menu), or `&stage=0` through `&stage=8` selects a stage for visual inspection; `&guide` loads simulated Touch Plus controller models and labels (`&hand=right` focuses the right controller). The small development toolbar calls the same actions as XR controls. It is removed from production builds; there is no desktop experience.

## Find Yourself

Enter VR from Quest Browser, then use a controller ray and trigger to choose an experience. The room scan has a separate mixed reality launch. Both controllers work. The presentation is placed relative to the initial viewing direction and eye height, supporting seated or standing use. Reset View places it in front of the current view. In the first three demos, guided lesson cards, status text, and action buttons sit in a raised band below eye level, with the floating models raised to keep them separate. This is a comfort-oriented placement choice based on [Meta's guidance](https://developers.meta.com/vr/design/mr-design-guideline/) to keep information slightly below sight and avoid UI falling too low; it is not a headset-certified angle. No persistent anchor, physical-table placement, or hand tracking is required.

Quest Touch shortcuts replace the persistent navigation row: **X** restarts the current experience, **Y** resets/recenters the view, **A** opens or closes a compact sound menu, and **B** leaves the current demo for the in-headset menu. On that menu, **B** exits VR or MR; X has no menu action. In the three landscape demos, the left thumbstick moves through the scene and the right thumbstick turns in 30° steps. The flat **Menu** button on the left controller is reserved by Quest Browser to leave WebXR, so the web app cannot bind it. Tracked controllers use locally bundled models from the [WebXR Input Profiles assets](https://github.com/immersive-web/webxr-input-profiles/tree/main/packages/assets), chosen from the headset's reported profile. When either controller is raised into the viewer's broad field of view, compact labels appear beside its actual button nodes after a brief glance. They remain visible during small gaze or wrist changes, then disappear after a short grace period or immediately on tracking loss/lowering. Paired labels stay outside their own buttons as the wrist turns; screen-space collision checks nudge nearby badges apart, hiding one only if no clear nearby position exists. Truly edge-on face-button pairs hide when their positions cannot be distinguished. These Quest-specific indices follow the [WebXR Input Profiles registry](https://github.com/immersive-web/webxr-input-profiles/tree/main/packages/registry); the [WebXR Gamepads specification](https://www.w3.org/TR/webxr-gamepads-module-1/#ua-platform-reserved-buttons) forbids exposing platform-reserved buttons, and [Meta's WebXR guidance](https://developers.meta.com/vr/documentation/web/webxr-hands/) says the left Menu button leaves a WebXR session. Actual Quest Browser model choice, guide alignment, legibility, and comfort still need headset validation.

Every dedicated takeaway screen also shows **Restart** and **Exit to Menu** buttons. They match X and B, so visitors can choose either the controller shortcuts or the visible actions.

0. The introduction defines GNSS (Global Navigation Satellite System), explains satellite-distance positioning, and establishes that each known beacon supplies distance without direction.
1. Each newly added range expands visibly from its known beacon; earlier circles stay in place at full size. One range defines a circle of possible model positions.
2. Two circles intersect at two selectable predictions.
3. A third range identifies one candidate; feedback explains either choice.
4. Toggle range tolerance; white dots satisfy all three bands.
5. In 3D, one beacon's distance creates a spherical shell of possible positions. The model floats independently of the text and controls. Point at it or reach nearby and hold a controller side grip to move/rotate the entire assembly. Add the other grip and spread/squeeze to resize uniformly (scale 0.28–0.85; default 0.35). Release to leave it in place.
6. Add a second shell. A bright circle highlights the positions where both exact distances agree; it fades in after the new shell expands.
7. Add a third shell. It cuts the two-shell intersection at two white candidate points; the highlighted circle disappears so the candidates stand out. Only the new shell expands; the earlier shells stay in place.
8. Add a fourth noncoplanar shell. Only the new shell expands, resolving the example while preserving your model position, rotation, and scale. Finish with takeaways.

The guided portion transitions to takeaways after 240 seconds of visible XR frame time. It can be completed sooner; paused/hidden sessions do not consume that time. Controller shortcuts for Restart, Reset View, Sound, and Exit demo remain available throughout. In 3D, Y/Reset View restores the default model pose and controls in front of the viewer. The assembly has a shared center; individual beacons cannot be moved independently because that would invalidate the measured-distance relationships. Tracking loss, hidden sessions, reset, or stage changes release active grips.

This is a scaled positioning model, **not a measurement of the visitor's real location**, a GPS implementation, or a probability model. Coordinates and tolerances use arbitrary model units. Headset tracking only places and views the content. The 3D example assumes exact ranges; GNSS pseudoranges also require estimating receiver clock error. Soft measurement and answer cues accompany visible changes. See SOURCES.md.

## Make It Rain

Choose **Make It Rain** inside the headset. The opening shows two clickable miniature terrain previews: **Drainage sandbox** and **Erosion tray**. Point at either surface and press the trigger to start that simulation. **Restart** returns to these choices. The drainage sandbox is a floating synthetic landscape with two outlets, a drainage divide, contour lines, and a movable rain cloud.

1. Choose the **Drainage sandbox** terrain thumbnail.
2. Point at the terrain and **hold the left trigger**. The cloud follows the aiming point and rain travels downhill. Releasing the trigger stops new rain; existing drops finish their paths. Try both sides of the ridge.
3. Toggle **Show basins** to color cells by their calculated outlet. Outlet A is blue and round; B is gold and square. Labels provide a cue independent of color.
4. Choose **Prediction**, then select which outlet will receive rain at the gold marker. Either answer reveals the computed path and an explanation. **Rain here again** replays it.
5. Read the takeaways or restart. The experience transitions to takeaways after four minutes of visible XR frame time.

During exploration, **hold the left trigger on land to add water** and **hold the right trigger on land to sculpt**. The right trigger locks the spot where the ray first hits the terrain; raise or lower that hand to build up or dig down at that spot. Sideways motion does not move the brush while the trigger is held. Release and point elsewhere to select a new spot. These work together without a mode switch, and editing preserves water and suspended sediment. One controller sculpts at a time. Rain continues at its last valid terrain position if the ray leaves the model. The golden sculpt cursor stays at its locked spot during the held stroke and disappears on release. Release the right trigger to refresh basin colors; new rain paths use the current terrain even during a stroke. **Reset terrain** restores the drainage landscape; **Reset** restores erosion. Edits are temporary and cleared by Restart or Exit demo. Heights are bounded and the rim anchored. Bare-hand tracking is not implemented.

To move the entire model, point at the terrain or reach near it and hold either **side grip**. Add the other grip to resize (scale 0.22–0.75). There are no separate grab handles. Left/right trigger roles use WebXR handedness, not controller connection order. Either trigger still selects UI buttons. **Reset View** restores pose and size without changing the experiment. Moving the model pauses new water input. Rotation changes the viewing angle, not simulated gravity. Hidden sessions, disconnects, and lost tracking release grabs/strokes.

After editing, blue/gold basin colors still indicate A/B; purple groups areas draining to any closed low spot (not one shared watershed). Rain particles deliver a fixed illustrative volume to their path endpoint. A conservative grid water model stores water in hollows, raises the surface, and transfers excess across the lowest wet spill edge into neighboring terrain. Cyan tiles show the water surface, with a bright moving shoreline; purple marks the original dry-terrain pond catchments, not eventual overflow destinations. A short cue marks the first detected transfer out of a closed sink. Water leaves at the open outer rim. Original contour and divide lines hide after editing so they cannot describe the old landscape. Trees follow the new surface. The prediction quiz is available on the original terrain; edited landscapes lead to takeaways. Sandbox time shares the four-minute experience cap.

The 65×65 elevation grid and steepest-descent paths are computed locally. The illustration uses arbitrary water volumes and a fixed-step surface-level relaxation model, not calibrated hydraulics. It does not simulate infiltration, evaporation, erosion, real rainfall intensity, momentum, or flood risk. Trees are decoration and do not change runoff. Pond surfaces use grid cells and may still look stepped along shorelines. Particle speed is illustrative; synthetic model units have no geographic scale. This is not a real watershed dataset.

For browser development review only, `?preview&demo=rain` opens the two-choice gallery; its thumbnails can be clicked to enter either simulation. Test buttons then emit rain on either slope; controller-ray selection still needs Quest verification. Production has no desktop experience.


### Erosion tray (inside Make It Rain)

Choose the **Erosion tray** terrain thumbnail at the Make It Rain opening. A slightly rough, loose-sediment bed replaces the drainage landscape. It starts pitched a little more toward the viewer, and the back-to-front bed grade is steeper so water has a stronger downhill path. The deeper base and increased cut limit leave more material available for channel formation during a sustained pour. Hold the left trigger over any chosen part of the bed to pour; release to stop adding water. Existing water keeps flowing. There are no start/stop pour controls. Flow cuts darker grooves, carries sediment, and can deposit lighter material downstream. Brown-tinted water indicates suspended sediment. **Reset** restores the original bed and clears water; it preserves the viewing pose. **Restart** returns to both terrain choices. Each experiment starts fresh and retains the four-minute wrap-up.

**Compare** overlays a denser white reference grid at the starting surface; it stays fixed while the actual terrain cuts down underneath. Darker grooves mark erosion and pale patches mark deposits. **Replay** plays saved bed states over four seconds with water paused, then restores the live simulation unchanged. It becomes useful after a few seconds of pouring; snapshots are kept only in memory. The loose-sand response is deliberately accelerated so channels become visible within about 10 seconds of sustained pouring. **Reset** restores the bed and hides the reference grid.

Right-trigger sculpting works while water flows. Manual edits shift the erosion reference by the amount moved, preserving previous erosion relative to that reference; they do not clear water or sediment or restart the experiment. The white grid follows these manual changes. **Reset** restores the factory landscape.

The erosion bed and water solver use a **65×65 grid** (4,225 samples; drainage also now uses 65×65). A translucent joined triangular water surface replaces flat water tiles; rendering only cells with at least two wet corners lets the changing bed remain visible. Terrain/water geometry refreshes at 10 Hz; the conservative simulation uses 50 fixed steps per second. A wet-bank slump transfers material from over-steep banks into adjacent cells, softening needle-like cuts while conserving earth. Shorelines are approximate at cell scale.

Either side grip moves/rotates the tray; both grips resize. Rotation changes the viewing pose, not the fixed physical slope. This experiment does not include soil selection, roots, rainfall calibration, or realistic time/length units. The erosion experiment routes each cell toward its steepest neighboring water-surface drop to emphasize rivulets; the pond experiment retains its multi-neighbor spreading rule. Sediment capacity is a heuristic based on local flux and slope; erosion is accelerated, limited to a 0.4-model-unit loose layer where the bed is thick enough, and the rim stays fixed. Sediment transfers use the water transfers and can leave the open rim. Channels are computed from evolving heights, not prerecorded lines. Water and sediment conservation are tested; this is not a predictive erosion model.

## Stand Inside the Layers

Choose the fourth experience in VR. A brief front-facing introduction explains that GIS organizes place information in layers and that the clipboard map and surrounding landscape show the same place. Select **Start building** to reveal the left-hand clipboard and begin the four-minute activity. The visitor stands in a 320-by-320-model-unit fictional landscape, with more distant terrain fading into the sky. Raise the left controller to view the overhead map and six layer checkboxes: **Topography**, **Vegetation**, **Hydrology**, **Roads**, **Floodplain**, and **Political boundaries**. Point with the right controller and press its trigger to toggle a layer; the change appears on the map and rises into the landscape over 0.8 seconds. Contextual hints connect each layer to a DEM, land cover, hydrography, transport, low river land, or human-drawn jurisdictions. The clipboard follows the left hand but stays at least 0.85 m from the viewer's eye; it disappears when left-controller tracking is unavailable. The left thumbstick moves through the landscape at walking speed, following the active terrain or road elevation; the right thumbstick turns the landscape in 30° steps, releasing between turns. Movement stops at the model's edge. The starting ground is flat and otherwise blank. Reset View returns the visitor to the center and restores the landscape orientation. The **Takeaway** button at the bottom of the clipboard opens the educational summary at any time; the same summary appears after four minutes. Its **Restart** and **Exit to Menu** buttons restart the activity or return to the gallery.

Topography spans 320-by-320 model units at 400-by-400 terrain cells, with denser vertices near the visitor, taller varied ridges, a three-band low-detail terrain skirt extending toward 480 model units, and more distant fog. The forest uses instanced trunks, near-field crown lobes, shrubs, and two tree forms at more than 2,000 shared positions. A river ribbon sits inside a carved channel; its water-surface elevation decreases continuously downstream. With Topography off, Hydrology is a nearly flush surface overlay on the flat ground. The Roads layer is a four-lane highway with shoulders draped into the terrain, lane markings, a bridge, supports, and rails. Walking onto a connected shoulder raises the visitor onto the highway and carries them across the bridge; walking along the river from below leaves them under the bridge. The same shared movement works in the viewshed and pixel demos. The 512-pixel clipboard map reuses these procedural alignments; a white dot follows the visitor as they move. A translucent blue floodplain marks low land near the river based on this synthetic elevation surface; it is neither a modeled inundation event nor a regulatory flood zone. Dashed magenta lines mark fictional political boundaries; they do not imply a physical barrier. Generated geometry has no runtime data download. Ground targeting in Viewshed and Pixel uses a separate 96-cell collision mesh while the full visual terrain remains unchanged.

Development-only `?preview&demo=layers` shows a stationary left-side clipboard and exposes its buttons in a browser for visual review. Left-hand tracking, right-controller checkbox selection, comfort, and frame rate still require Quest validation.

## Can You See It?

Choose the fifth experience in VR to explore a terrain-only viewshed on the **same generated ground** as Stand Inside the Layers. This demo hides the forest and highway, leaving the river as a landmark so the visible landscape matches the bare-earth elevation model used by the calculation. A short introduction defines a viewshed and asks how ridges and observer height affect visibility; select **Test the view** to begin the four-minute session and reveal the left-hand clipboard. A gold marker starts at the visitor's location; a blue ground target poses a lookout question. Point at the clipboard map and press the trigger to move the observer, or point at the terrain itself. The left thumbstick moves the visitor, shown as a white ring on the map; the right thumbstick turns the world in 30° steps. The gold observer is independent of the visitor. An animated sightline stops at the first blocking terrain or reaches the target. The green overlay fades in over ground with an unobstructed terrain sightline; purple marks ground hidden by higher terrain. Compare **Eye level · 2 m** with **Tower · 12 m**, or move the marker to a ridge. The observer mast rises as the visibility result updates. The map and landscape use the same calculated visibility grid. **Reset point** returns the marker to the center and eye level. The **Takeaway** button at the bottom of the clipboard opens the DEM, ridge, and observer-height summary at any time; it also appears after four minutes, with **Restart** and **Exit to Menu** actions.

The analysis samples a procedural elevation model on a 321-by-321 grid, checks line of sight to 161-by-161 ground cells within 125 model units, and updates when the marker or height changes. The percentage describes sampled ground within the analysis radius. A site-specific analysis could add tree canopies and structures with a surface model; atmospheric effects and Earth curvature are outside this teaching model. Development-only `?preview&demo=viewshed` shows the clipboard and its controls. Quest controller targeting, map readability, stereo contrast, and frame rate still require headset testing.

## How Big Is a Pixel?

Choose the sixth experience in VR. It uses the same synthetic terrain, forest, river, and highway as the Layers experience; Viewshed uses this same ground with the forest and highway hidden. A short introduction defines ground sample distance and explains why large pixels mix narrow features; select **Compare pixels** to begin the four-minute session and reveal the left-hand clipboard. A gold outline on the ground marks the area represented by one pixel. The larger clipboard shows the **same 144 m ground window side by side** at fixed 2 m pixels and a selectable **2 m, 8 m, 24 m, or 48 m** comparison size. The left thumbstick moves the visitor and the right thumbstick turns the world in 30° steps. A white dot on each image marks the visitor while inside that image window. The ground outline grows or shrinks over 0.7 seconds while the landscape stays the same. Point at either image or the terrain and press the trigger to select another pixel. The clipboard shows that pixel's area and cover proportions, then asks whether any 48 m pixel remains entirely water. The **Takeaway** button at the bottom of the clipboard opens the ground sample distance and mixed-pixel summary at any time; it also appears after four minutes, with **Restart** and **Exit to Menu** actions.

The image covers a 144-by-144-model-meter window centered on the visitor. Its 1 m synthetic land-cover samples are grouped into larger square pixels, and each displayed RGB value is the arithmetic mean of the model colors in that square. Tree canopies, river width, and highway position come from the same procedural world geometry, but the image is **not** satellite imagery or a physical sensor simulation: it does not model reflectance, optics, atmosphere, geolocation error, or real measured land cover. The square outline and area display teach nominal ground pixel size. Development-only `?preview&demo=pixels` supports visual review; Quest clipboard legibility, ground-targeting, and frame rate still need headset testing.

## See the Invisible

The seventh experience starts with the electromagnetic spectrum: humans see visible light, while sensors can measure near infrared. After **Reveal the bands**, visitors explore three real, aligned natural/false-color image pairs: San Francisco Bay (Landsat 5, 1997), the Everglades and Miami (Landsat 5, 2011), and Lilongwe, Malawi (Landsat 8, 2018). The **Next scene** button cycles through all three before repeating; the Bay opens first, then the other scenes appear in a shuffled order. Florida's leafy fields and wetlands show a strong vegetation–water contrast, while Lilongwe reveals trees along streams and in neighborhoods. **Natural color** displays visible red/green/blue; **False color** assigns near infrared to display red, visible red to green, and visible green to blue. **NIR only** extracts the false-color image's red display channel as an approximate grayscale NIR view. The selected view button is highlighted, including after changing scenes. Point and trigger on the image to compare displayed band brightnesses. **Takeaways** opens a short, scene-specific explanation and can be revisited before the four-minute ending.

The source composites are real Landsat-derived visualizations, not raw band data. The bars sample rendered JPEG display values; they are **not** calibrated reflectance, NDVI, a vegetation-health diagnosis, or a quantitative comparison between independently stretched bands. The Lilongwe natural-color image is pan-sharpened and downsampled to align with its false-color display image. The terrain in NASA's oblique Bay rendering is exaggerated threefold. Development preview: `?preview&demo=spectral`.

## Where Did the Cluster Go?

The eighth experience uses 250 mapped Soho buildings, 40 mapped housing blocks, and eight pumps from GeoDa's digitizations of Snow's 1855 Broad Street map. The building and block datasets each total 489 recorded deaths **in these particular source files**, not every cholera death in the outbreak. **Buildings** shows the mapped points, with circle size representing death count, and the street corridors between blocks. **Plan A**, **Plan B**, **Plan C**, and **Plan D** group whole housing blocks into hypothetical administrative zones of six, six, five, and seven wards. The plans change both boundaries and aggregation level while preserving all 489 recorded deaths. The selected plan is highlighted. Point at a colored block to read its ward's death count just above the plan buttons. The light-to-dark blue sequential legend represents **recorded death counts per ward**, not mortality rates: no population denominator is available. Yellow marks the Broad Street pump and cyan marks the seven other mapped pumps in every view. Ward boundaries follow the gaps between the source blocks rather than a square grid. They are teaching examples, not historical wards or reconstructions of Monmonier's specific map panels. The source's separate building and block digitizations align approximately but do not place every building point inside its corresponding polygon, so ward totals come directly from the block dataset rather than a spatial join of the displayed points.

The **Takeaway** button opens a summary at any point, and the same screen appears after four minutes with **Restart** and **Exit to Menu**. The lesson is inspired by Mark Monmonier's Snow-map aggregation example in *How to Lie with Maps*. It explains that aggregating building deaths into administrative wards can hide a street-level concentration and that the modifiable areal unit problem (MAUP) can change a map's apparent pattern without moving any underlying observations. It does not establish a statistically significant cluster or prove a causal source. Development preview: `?preview&demo=cluster`.

## Make the World Flat

The ninth experience displays a slowly rotating globe beside the same public-domain Natural Earth land outlines on a surface that unfolds into a flat map. Visitors can discover that holding a controller trigger on the globe spins or tilts it; vertical drag stays screen-consistent as the Pacific side comes into view, and a swipe coasts before the gentle default spin resumes. The visitor can choose **Plate Carrée** (equirectangular), **Mercator**, or **Cylindrical equal-area**; **Wrap/Flatten** animates the transformation. Dragging the flat map left or right moves the central meridian continuously; in equal-area mode the standard parallel can be switched between 0° and 30°. The equator and Prime Meridian are emphasized on both views. **Tissot circles** overlays equal-size small circles on the source globe and their projected shapes on the map. Six longitude columns are evenly spaced at 60° intervals, including the Pacific seam. A trigger tap on a circle highlights the same geographic circle on globe and map; tapping elsewhere clears the selection, while dragging the globe spins it. The active projection button is highlighted. Roundness indicates local shape distortion and relative size indicates local area distortion. These finite 8°-radius symbols approximate the infinitesimal indicatrix. Each projection is fit with a uniform display scale to avoid adding artificial shape distortion. A readout compares each projection's local map-area scale at 60° N with the equator: approximately 2×, 4×, and 1×, respectively. The projection mesh has about 4,700 vertices and updates locally in the browser, so the interactive choices require no server or runtime download. The **Takeaway** button opens a dedicated summary of distortion and projection choices at any time; it also appears after four minutes with **Restart** and **Exit to Menu**. This is a teaching comparison of three cylindrical projections, not a general-purpose projection editor. Development preview: `?preview&demo=projection`; use the mouse to spin the globe, recenter the map, and select Tissot circles there.

Each of these experiences starts its four-minute timer only after its introduction button is pressed. **X** restarts it, **Y** recenters the display, **A** opens the existing sound menu, and **B** returns to the ten-demo gallery. On Quest, check gallery readability and targeting as well as the demos' frame rate and transitions.

## What Changed?

The tenth experience uses three real USGS Earthshots Landsat pairs: the June 2007–June 2008 Illinois/Indiana flood, Yellowstone before and after the 1988 fires, and northeastern Dallas in March 1989 and March 2023. The same scene fills a floating image panel; drag the white divider to compare dates. The image and answer buttons share a plane. Choose an interpretation to reveal a highlighted example area, a brief explanation, and the next place. After the third case, **Show Takeaway** opens a summary of change detection, aligned images, matching season and bands, and corroborating records. **Restart** and **Exit to Menu** are visible there. The lesson also wraps up after four minutes. Development preview: `?preview&demo=change`.

The JPEGs are locally bundled encodings of the original USGS Earthshots PNGs. The two frames in each case are shown at the same extent without generated pixels. The Dallas source frames differ by one pixel in height and are normalized on the display canvas. Colors come from each source's infrared composite; the lesson asks visitors to recognize visible patterns, while the short interpretation relies on the USGS event description. These rendered images are for visual interpretation rather than calibrated pixel-by-pixel change measurement. See SOURCES.md for dates, bands, image provenance, and reuse terms.

## Scan the Hidden World

Choose the third experience in the shared menu, then select **Synthetic scan** or **Room scan · MR** from the two cards. The choice screen briefly explains that lidar (Light Detection and Ranging) times returning laser pulses to build a 3D point cloud. The synthetic scan opens an outlined miniature scene; hold the trigger and sweep a controller through it to collect a point cloud. It illustrates first-surface sampling without using a laser or measuring return time. One side grip moves/rotates the model; while a grip is held, that controller’s stick snaps the model 45° left, right, up, or down once per deflection. Both grips resize it (0.22–0.75, default 0.43). Rotate and scan another side to observe formerly blocked surfaces. **Reset View** restores the pose without discarding points.

Seven original procedural scenes rotate in shuffled order: **Woodland ruins**, **Ravine bridge**, **Hillside village**, **Terraced lookout**, **Forest survey**, **Covered courtyard**, and **Survey tower**. They demonstrate occlusion, under-deck and interior blind spots, canopy obstruction, elevation sampling, and narrow-feature point density. Starting or restarting the synthetic experience draws the next scene, with every scene appearing once per cycle and no immediate repeats across cycles. Restart begins another run with the next scene. Rotation is per app session; scenes never change during an active scan. **Clear scan** keeps the current scene. Real-room scanning is independent.

**Show scene** replaces the point cloud with a shaded, procedurally textured reference model of the same ground, structures, and trees; **Cloud only** returns to the samples. The model is a stylized scene, not a photographic reconstruction. A brief ray shows each central first-surface return, and newly acquired points brighten before settling into ground/structure/vegetation colors. **Hide plants** filters vegetation points, with **All points** restoring them. Filtering never changes what blocks a scan ray and never invents returns from unseen ground. Each scene presents a scan challenge and its own short takeaway connecting the observation to lidar survey concepts such as occlusion, overlapping viewpoints, point density, and digital elevation models. **Clear scan** discards observations during a run. The takeaway hides the model and scan, showing only the summary plus **Restart** and **Exit to Menu**. Each run wraps up after four minutes of visible session time.

This is a controller-driven illustration of first-surface range sampling. It does not use Quest room meshes, depth sensors, cameras, real lidar, multiple returns, or automated classification. Color/class labels come from known synthetic objects. Each sweep fires a small cone of rays; only the nearest hit is recorded. Samples are deduplicated in model coordinates and capped at 18,000. No scan leaves the device or persists after restart. Modeled scene positions and classifications are exact; real scanning also has measurement and positioning errors. See SOURCES.md for USGS background.

Development-only `?preview&demo=scan` provides front/back sampling actions through the same nearest-hit routine for repeatable visual review. Add `&scene=ruins`, `bridge`, `village`, `terraces`, `canopy`, `courtyard`, or `tower` to inspect a particular model. These controls are excluded from production; real controller sweeping still needs headset verification.

### Scan your room (experimental Quest 3S path)

From the VR scan choice screen, choose **Room scan · MR**. The app ends VR and requests a mixed reality session directly. If Quest requires a fresh user gesture, choose **Open room scan in MR** on the browser page. You can also launch the room scan from that page. Once in MR, choose **Start room scan**; **B** returns to a small MR menu and pressing **B** again exits MR. Use the browser's VR button to reopen the other experiences. Allow the browser's spatial permission if requested. Aim a controller at nearby physical surfaces; up to three green dots indicate actual WebXR hit-test returns in a short horizontal fan. Hold the trigger and sweep to accumulate a point cloud. This path requests the WebXR `hit-test` feature and default plane-type surface estimates. It does not claim access to raw live depth, a global mesh, photogrammetry, camera images, or semantic classification; the runtime determines which surfaces are represented and whether its data is reconstructed or updated live.

**Freeze** centers and scales a copy of the recorded points in front of you. Use one/two side grips to move/rotate/resize it. **Resume** restores the original recorded room coordinates. **Color** switches relative-height versus capture-range coloring. **Clear** discards points; **Retry** retries source creation when surface access fails or no hits arrive. **Takeaways** opens the summary whenever the visitor is ready. Room registration is preserved during Reset View while live; only the controls move. Reset View restores the miniature when frozen.

No synthetic positions are substituted for missing real data. Unsupported API, rejected permission, and no-hit states are shown explicitly. Each tracked controller keeps a center hit-test source and requests two angled `offsetRay` sources. If the browser rejects either extra source, the center scan continues. Only returned poses become dots; the fan never fills in gaps by interpolation. Samples are deduplicated at 1.5 cm, restricted to 0.2–8 m range, and capped at 18,000. These limits are application choices, not sensor accuracy claims. Captures stay in memory and clear on restart, session exit, or reference-space reset. The visitor can open takeaways early; the four-minute wrap-up also freezes the cloud if it contains points. Keep passthrough visible; do not treat the cloud as a complete obstacle map.

Device acceptance is still required on Quest 3S: API availability, actual surface-return quality, permissions, registration stability, tracking recovery, and useful point density. Desktop checks use mocked API results and cannot establish those properties.

- All text is readable and geometry remains stable in stereo.

## Sound effects

Original Web Audio synthesis provides a quiet looping lounge melody on the in-headset menu, soft UI tones, distinct measurement/reveal/answer/layer/overflow/pixel cues, rate-limited pings for newly collected scan points (including room scans), and filtered water noise that begins with rain/pour input and fades shortly after release. The three landscape demos have soft wind; bird calls and leaves fade in when the vegetation layer is visible, and a stream sound grows nearer to the river when hydrology is visible. Menu music fades out when a demo starts. Synthetic scan ping pitch varies slightly with return distance; it does not encode material. No sound files or external audio services are loaded. **A** on the right controller opens a small, world-anchored sound menu from the main menu or any demo. It controls master mute, 0–100% volume, menu music, nature ambience, and effects independently; A or **Close** dismisses it. The lesson timer and scene interactions pause while it is open. Preferences are remembered locally when browser storage is available. Audio initializes on XR entry, fades out when the page/XR session is hidden, and remains optional if audio is unavailable. Quest loudness and comfort require headset listening. Implementation follows [MDN Web Audio best practices](https://developer.mozilla.org/en-US/docs/Web/API/Web_Audio_API/Best_practices).
