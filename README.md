# Spatial Discovery Lab — GIS Day

Quest-focused WebXR app with twelve short experiences in one immersive selection gallery: **Stand Inside the Layers**, **Find Yourself**, **Make the World Flat**, **Can You See It?**, **Between the Rain Gauges**, **Make It Rain**, **Where Did the Cluster Go?**, **Scan the Hidden World**, **See the Invisible**, **How Big Is a Pixel?**, **What Changed?**, and **GeoSlice Challenge**. The four-column gallery curves gently toward the viewer. Each card gives a one-sentence preview; a controller ray and trigger open any demo directly. **Where Should It Go?** remains in the codebase as a paused prototype and is hidden from the gallery.

## Run

Node 22 recommended.

```sh
npm ci
npm run dev
npm test
npm run build
```

Production: serve `dist/` over HTTPS. Quest cannot use ordinary HTTP from a laptop's LAN address for immersive WebXR. GitHub Pages supplies HTTPS. The gallery demos need no runtime API keys or external asset requests; the separate recommended-video gallery loads YouTube thumbnails and embedded videos from YouTube when opened. Dependencies are bundled by Vite.

## Find Yourself

Enter VR from Quest Browser, then use a controller ray and trigger to choose an experience. The room scan has a separate mixed reality launch. Both controllers work. The presentation is placed relative to the initial viewing direction and eye height, supporting seated or standing use. Reset View places it in front of the current view. In the GNSS, rain, and scan demos, guided lesson cards, status text, and action buttons sit in a raised band below eye level, with the floating models raised to keep them separate. This is a comfort-oriented placement choice based on [Meta's guidance](https://developers.meta.com/vr/design/mr-design-guideline/) to keep information slightly below sight and avoid UI falling too low; it is not a headset-certified angle. No persistent anchor, physical-table placement, or hand tracking is required.

Quest Touch shortcuts replace the persistent navigation row: **X** restarts the current experience, **Y** resets/recenters the view, **A** opens or closes a compact sound menu, and **B** leaves the current demo for the in-headset menu. On that menu, **B** exits VR or MR; X has no menu action. In the three landscape demos, the left thumbstick walks; moving the right thumbstick sideways turns in 30° steps. Holding the right thumbstick forward activates a landing marker at the right controller ray's terrain hit; releasing the stick to center teleports there. Steep, out-of-bounds, obstructed, and distant landing spots are rejected. An exposed road deck can be selected to land on the bridge. The flat **Menu** button on the left controller is reserved by Quest Browser to leave WebXR, so the web app cannot bind it. Tracked controllers use locally bundled models from the [WebXR Input Profiles assets](https://github.com/immersive-web/webxr-input-profiles/tree/main/packages/assets), chosen from the headset's reported profile. When either controller is raised into the viewer's broad field of view, compact labels appear beside its actual button nodes after a brief glance. They remain visible during small gaze or wrist changes, then disappear after a short grace period or immediately on tracking loss/lowering. Paired labels stay outside their own buttons as the wrist turns; screen-space collision checks nudge nearby badges apart, hiding one only if no clear nearby position exists. Truly edge-on face-button pairs hide when their positions cannot be distinguished. These Quest-specific indices follow the [WebXR Input Profiles registry](https://github.com/immersive-web/webxr-input-profiles/tree/main/packages/registry); the [WebXR Gamepads specification](https://www.w3.org/TR/webxr-gamepads-module-1/#ua-platform-reserved-buttons) forbids exposing platform-reserved buttons, and [Meta's WebXR guidance](https://developers.meta.com/vr/documentation/web/webxr-hands/) says the left Menu button leaves a WebXR session. Actual Quest Browser model choice, guide alignment, legibility, and comfort still need headset validation.

If Quest Browser and both expected Touch input profiles are not present, the app shows **Restart**, **Reset**, **Sound**, and **Exit** at the bottom of each immersive demo. The in-headset gallery shows **Reset**, **Sound**, and **Exit VR/MR**; the initial guide shows **Reset**, **Sound**, and **Skip**. On the three walkable landscapes, these actions sit below the existing clipboard controls. The clipboard stays accessible in front of the viewer when a left grip is unavailable. The fallback is based on live WebXR input profiles and browser identification, so an uncertain match gets visible controls rather than an assumed face-button mapping. A non-Quest device still needs a browser and hardware that support immersive WebXR and the particular demo's features; room scanning additionally needs MR hit testing. These paths require testing on the target headset.

Every dedicated takeaway screen also shows **Restart** and **Exit to Menu** buttons. They match X and B, so visitors can choose either the controller shortcuts or the visible actions.

1. Each newly added range expands visibly from its known beacon; earlier circles stay in place at full size. One range defines a circle of possible model positions.
2. Two circles intersect at two selectable predictions.
3. A third range identifies one candidate; feedback explains either choice.

5. In 3D, one beacon's distance creates a spherical shell of possible positions. The model floats independently of the text and controls. Release to leave it in place.
6. Add a second shell. A bright circle highlights the positions where both exact distances agree; it fades in after the new shell expands.
7. Add a third shell. It cuts the two-shell intersection at two white candidate points; the highlighted circle disappears so the candidates stand out. Only the new shell expands; the earlier shells stay in place.
8. Add a fourth noncoplanar shell. Only the new shell expands, resolving the exact-range example while preserving your model position, rotation, and scale.
9. Grip and turn an original procedural, GPS III-inspired satellite model. Trigger-select its segmented solar wings, insulated bus, or Earth-facing antenna deck to identify their roles. The controller ray passes through the decorative radio halo to the solid part being inspected.
10. Press **Send pulse** to launch an expanding radio wavefront toward a model receiver. The pulse animation is slowed for viewing; a 20,200 km example takes about 67.4 ms at light speed. **Send again** repeats it.
11. Compare a receiver clock that is 1 microsecond fast (about 300 m added to each pseudorange) with a corrected solution by selecting **Use fourth signal**. Three spacecraft are present initially; the fourth appears only on correction.
12. Select **Open sky** and **City canyon** to compare animated direct and reflected signal routes. In the canyon, one building interrupts the straight path while the longer route reflects off another facade and arrives later. That delay makes the measured distance too large and can shift the calculated location. Both choices reveal **Takeaway**.

Controller shortcuts for Restart, Reset View, Sound, and Exit demo remain available throughout. In 3D, Y/Reset View restores the default model pose and controls in front of the viewer. The assembly has a shared center; individual beacons cannot be moved independently because that would invalidate the measured-distance relationships. Tracking loss, hidden sessions, reset, or stage changes release active grips.

This is a scaled positioning model, **not a measurement of the visitor's real location**, a GPS implementation, or a probability model. Coordinates and tolerances use arbitrary model units. Headset tracking only places and views the content. The 3D beacon example assumes exact ranges; GNSS pseudoranges also require estimating receiver clock error. The spacecraft and urban-canyon models are illustrative, and the wavefront animation is slowed. Soft measurement and answer cues accompany visible changes. See SOURCES.md.

## Make It Rain

Choose **Make It Rain** inside the headset. The opening shows two clickable miniature terrain previews: **Drainage sandbox** and **Erosion tray**. Point at either surface and press the trigger to start that simulation. **Restart** returns to these choices. The drainage sandbox is a floating synthetic landscape with two outlets, a drainage divide, contour lines, and a movable rain cloud.

1. Choose the **Drainage sandbox** terrain thumbnail.
2. Point at the terrain and **hold the left trigger**. The cloud follows the aiming point and rain travels downhill. Releasing the trigger stops new rain; existing drops finish their paths. Try both sides of the ridge.
3. Toggle **Show basins** to color cells by their calculated outlet. Outlet A is blue and round; B is gold and square. Labels provide a cue independent of color.
4. Choose **Prediction**, then select which outlet will receive rain at the gold marker. Either answer reveals the computed path and an explanation. **Rain here again** replays it.
5. Read the takeaways or restart. The experience transitions to takeaways after four minutes of visible XR frame time.

During exploration, **hold the left trigger on land to add water** and **hold the right trigger on land to sculpt**. The right trigger locks the spot where the ray first hits the terrain; raise or lower that hand to build up or dig down at that spot. Sideways motion does not move the brush while the trigger is held. Release and point elsewhere to select a new spot. These work together without a mode switch, and editing preserves water and suspended sediment. One controller sculpts at a time. Rain continues at its last valid terrain position if the ray leaves the model. The golden sculpt cursor stays at its locked spot during the held stroke and disappears on release. Release the right trigger to refresh basin colors; new rain paths use the current terrain even during a stroke. **Reset terrain** restores the drainage landscape; **Reset** restores erosion. Edits are temporary and cleared by Restart or Exit demo. Heights are bounded and the rim anchored. Bare-hand tracking is not implemented.

To move the entire model, point at the terrain or reach near it and hold either **side grip**. While holding a grip, push that controller's stick left, right, up, or down to snap-turn the model 45°; release the stick before the next turn. Add the other grip to resize (scale 0.22–0.75). There are no separate grab handles. Left/right trigger roles use WebXR handedness, not controller connection order. Either trigger still selects UI buttons. **Reset View** restores pose and size without changing the experiment. Moving the model pauses new water input. Rotation changes the viewing angle, not simulated gravity. Hidden sessions, disconnects, and lost tracking release grabs/strokes.

After editing, blue/gold basin colors still indicate A/B; purple groups areas draining to any closed low spot (not one shared watershed). Rain particles deliver a fixed illustrative volume to their path endpoint. A conservative grid water model stores water in hollows, raises the surface, and transfers excess across the lowest wet spill edge into neighboring terrain. Cyan tiles show the water surface, with a bright moving shoreline; purple marks the original dry-terrain pond catchments, not eventual overflow destinations. A short cue marks the first detected transfer out of a closed sink. Water leaves at the open outer rim. Original contour and divide lines hide after editing so they cannot describe the old landscape. Trees follow the new surface. The prediction quiz is available on the original terrain; edited landscapes lead to takeaways. Sandbox time shares the four-minute experience cap.

The 65×65 elevation grid and steepest-descent paths are computed locally. The illustration uses arbitrary water volumes and a fixed-step surface-level relaxation model, not calibrated hydraulics. It does not simulate infiltration, evaporation, erosion, real rainfall intensity, momentum, or flood risk. Trees are decoration and do not change runoff. Pond surfaces use grid cells and may still look stepped along shorelines. Particle speed is illustrative; synthetic model units have no geographic scale. This is not a real watershed dataset.

For browser development review only, `?preview&demo=rain` opens the two-choice gallery; its thumbnails can be clicked to enter either simulation. Test buttons then emit rain on either slope; controller-ray selection still needs Quest verification. Production has no desktop experience.


### Erosion tray (inside Make It Rain)

Choose the **Erosion tray** terrain thumbnail at the Make It Rain opening. A slightly rough, loose-sediment bed replaces the drainage landscape. It starts pitched a little more toward the viewer, and the back-to-front bed grade is steeper so water has a stronger downhill path. The increased cut limit leaves more material available for channel formation during a sustained pour. Both models show a bottom and corner frame with translucent soil sides that follow the displayed terrain edge, keeping the soil depth legible without an opaque black wall. Hold the left trigger over any chosen part of the bed to pour; release to stop adding water. Existing water keeps flowing. Flow cuts darker grooves, carries sediment, and can deposit lighter material downstream. Brown-tinted water indicates suspended sediment. **Reset** restores the original bed, removes vegetation, and clears water; it preserves the viewing pose. **Restart** returns to both terrain choices. Each experiment starts fresh and retains the four-minute wrap-up.

**Compare** overlays a denser white reference grid at the starting surface; it stays fixed while the actual terrain cuts down underneath. Darker grooves mark erosion and pale patches mark deposits. **Replay** plays saved bed states over four seconds with water paused, then restores the live simulation unchanged. It is available on the Takeaway screen after the bed changes; playback temporarily clears the takeaway text and returns there when it ends. Snapshots are kept only in memory. The loose-sand response is deliberately accelerated so channels become visible within about 10 seconds of sustained pouring. **Reset** restores the bed and hides the reference grid.

Right-trigger sculpting works while water flows. Manual edits shift the erosion reference by the amount moved, preserving previous erosion relative to that reference; they do not clear water or sediment or restart the experiment. The white grid follows these manual changes. **Reset** restores the factory landscape.

Select **Plants** on the bottom action row to turn the right trigger into a vegetation brush. Sweep its green cursor over the tray to paint connected green patches while the left trigger keeps raining. Select **Plants** again to return to the earth-sculpting brush. Fully vegetated cells lose soil at about 6% of the bare-soil detachment and wet-bank slumping rates in this illustrative model; water still crosses the patch and carries sediment. Paint one strip and leave another bare to compare their changing channels. Replay includes the green cover present in each saved bed state. **Reset** clears the cover.

The erosion bed and water solver use a **65×65 grid** (4,225 samples; drainage also now uses 65×65). A translucent joined triangular water surface replaces flat water tiles; rendering only cells with at least two wet corners lets the changing bed remain visible. Terrain/water geometry refreshes at 10 Hz; the conservative simulation uses 50 fixed steps per second. A wet-bank slump transfers material from over-steep banks into adjacent cells, softening needle-like cuts while conserving earth. Shorelines are approximate at cell scale.

Either side grip moves/rotates the tray; both grips resize. Rotation changes the viewing pose, not the fixed physical slope. The painted cover stands in for plants and their soil-binding roots; the model does not simulate individual roots, infiltration, rainfall calibration, or realistic time/length units. The erosion experiment routes each cell toward its steepest neighboring water-surface drop to emphasize rivulets; the pond experiment retains its multi-neighbor spreading rule. Sediment capacity is a heuristic based on local flux and slope; erosion is accelerated, limited to a 0.4-model-unit loose layer where the bed is thick enough, and the rim stays fixed. Sediment transfers use the water transfers and can leave the open rim. Channels are computed from evolving heights, not prerecorded lines. Water and sediment conservation are tested; this is not a predictive erosion model.

## Stand Inside the Layers

Choose the first experience in VR. A brief front-facing introduction explains that GIS organizes place information in layers and that the clipboard map and surrounding landscape show the same place. Select **Start building** to reveal the left-hand clipboard and begin the four-minute activity. The visitor stands in a 320-by-320-model-unit fictional landscape, with more distant terrain fading into the sky. Raise the left controller to view the overhead map and six layer checkboxes: **Topography**, **Vegetation**, **Hydrology**, **Roads**, **Floodplain**, and **Political boundaries**. Point with the right controller and press its trigger to toggle a layer; the change appears on the map and rises into the landscape over 0.8 seconds. Contextual hints connect each layer to a DEM, land cover, hydrography, transport, low river land, or human-drawn jurisdictions. The clipboard follows the left hand but stays at least 0.85 m from the viewer's eye; it disappears when left-controller tracking is unavailable. The left thumbstick moves through the landscape at walking speed, following the active terrain or road elevation; the right thumbstick turns the landscape in 30° steps, releasing between turns. Movement stops at the model's edge. The starting ground is flat and otherwise blank. Reset View returns the visitor to the center and restores the landscape orientation. The **Takeaway** button at the bottom of the clipboard opens the educational summary at any time; the same summary appears after four minutes. Its **Restart** and **Exit to Menu** buttons restart the activity or return to the gallery.

Topography spans 320-by-320 model units at 400-by-400 terrain cells, with denser vertices near the visitor, taller varied ridges, a three-band low-detail terrain skirt extending toward 480 model units, and more distant fog. The forest uses instanced trunks, near-field crown lobes, shrubs, and two tree forms at more than 2,000 shared positions. A river ribbon sits inside a carved channel; its water-surface elevation decreases continuously downstream. With Topography off, Hydrology is a nearly flush surface overlay on the flat ground. The Roads layer is a four-lane highway with shoulders draped into the terrain, lane markings, a bridge, supports, and rails. Walking onto a connected shoulder raises the visitor onto the highway and carries them across the bridge; walking along the river from below leaves them under the bridge. The same shared movement works in the viewshed and pixel demos. The 512-pixel clipboard map reuses these procedural alignments; a white dot follows the visitor as they move. A translucent blue floodplain marks low land near the river based on this synthetic elevation surface; it is neither a modeled inundation event nor a regulatory flood zone. Dashed magenta lines mark fictional political boundaries; they do not imply a physical barrier. Generated geometry has no runtime data download. Ground targeting in Viewshed and Pixel uses a separate 96-cell collision mesh while the full visual terrain remains unchanged.

Development-only `?preview&demo=layers` shows a stationary left-side clipboard and exposes its buttons in a browser for visual review. Left-hand tracking, right-controller checkbox selection, comfort, and frame rate still require Quest validation.

## Can You See It?

Choose the fourth experience in VR to explore a terrain-only viewshed. The clipboard offers two synthetic landscapes: the original **River Valley** shared with Stand Inside the Layers, and **Redrock Bend**, a winding canyon with steep walls. Each scene has its own map, elevation grid, blue target, walking height, and visibility overlay. The demo hides forest and highway in the original valley, leaving the river as a landmark so the visible landscape matches the bare-earth elevation model used by the calculation. A short introduction defines a viewshed and asks how ridges and observer height affect visibility; select **Test the view** to begin the four-minute session and reveal the left-hand clipboard. A gold tower starts a few steps ahead of the visitor; a blue ground target poses a lookout question. Point at the clipboard map and press the trigger to move the observer, or point at the terrain itself. The left thumbstick moves the visitor, shown as a white ring on the map; the right thumbstick turns the world in 30° steps. The gold observer is independent of the visitor. An animated sightline stops at the first blocking terrain or reaches the target. The green overlay fades in over ground with an unobstructed terrain sightline; purple marks ground hidden by higher terrain. The two observer heights form one radio choice on the clipboard, with a filled circle and highlight marking the current selection. Compare **Eye level · 2 m** with **Tower · 12 m**, or move the marker to a ridge.

At **Eye level · 2 m**, the pole is short and has no steps. Selecting **Tower · 12 m** extends it and reveals alternating side-mounted climbing pegs anchored in the pole. A square opening in the lookout deck leaves room to climb through. Hold a controller grip near a peg and pull that hand down to climb; either hand can hold one. Releasing both grips before the top drops the visitor to the ground. Near the top, gripping the platform rim smoothly pulls the visitor up and onto a hands-free lookout, then restores the clipboard. Pulling above the top peg also reaches the lookout. The right-stick teleport ray can land on the platform and lock the visitor into the same lookout position. From the platform, gripping the pole smoothly returns the visitor to the rungs; hand movements then control descent, and releasing the grip drops them to the ground. Walking, teleporting, and tower placement pause at the top; turning and clipboard controls remain available. The tall tower and its 12 m viewshed stay selected after a drop until **Eye level · 2 m** is chosen. The map and landscape use the same calculated visibility grid. **Reset point** returns the marker to its starting position and eye level. The **Takeaway** button at the bottom of the clipboard opens the DEM, ridge, and observer-height summary at any time; it also appears after four minutes, with **Restart** and **Exit to Menu** actions.

The analysis samples a procedural elevation model on a 321-by-321 grid, checks line of sight to 161-by-161 ground cells within 125 model units, and updates when the marker or height changes. The percentage describes sampled ground within the analysis radius. A site-specific analysis could add tree canopies and structures with a surface model; atmospheric effects and Earth curvature are outside this teaching model. Development-only `?preview&demo=viewshed` shows the clipboard and its controls. Quest controller targeting, map readability, stereo contrast, and frame rate still require headset testing.

## How Big Is a Pixel?

Choose the tenth experience in VR. It begins with a short introduction to ground sample distance (GSD) and models of a satellite, aircraft, and drone. **Enter pixel landscape** opens the walkable synthetic terrain, forest, river, and highway shared with Stand Inside the Layers. The clipboard offers **Ground footprint** and **Pixelated world** views, plus 50 cm, 2 m, 10 m, and 30 m pixel sizes. In Ground footprint, a gold outline marks one pixel on the detailed terrain; selecting a size sends the corresponding drone, aircraft, or satellite marker overhead. In Pixelated world, the same landscape is colored by square cells whose colors average the land cover inside each selected pixel. Individual trees, river, road, and the gold outline are hidden in that view, and flyovers stop. The terrain shape remains walkable in both views. The clipboard maps compare a fixed 50 cm image with the selected size over the same 144 m ground window. Point at a map or the ground to select a cell and see its area and forest, water, road, and other-ground proportions. The clipboard also asks whether any 30 m cell is entirely water. **Takeaway** opens the mixed-pixel summary with **Restart** and **Exit to Menu**.

The clipboard image covers a 144-by-144-model-meter window centered on the landscape origin. Its 50 cm synthetic land-cover samples are grouped into larger square pixels, and each displayed RGB value is the arithmetic mean of the model colors in that square. The pixelated world uses the same sampling rule across the 320 m walkable terrain, with its cell grid aligned to the clipboard maps. Tree canopies, river width, and highway position come from the same procedural world geometry. These images illustrate spatial resolution; they do not simulate a particular sensor's reflectance, optics, atmosphere, or measured land cover. Development-only `?preview&demo=pixels` supports visual review; Quest clipboard legibility, ground-targeting, and frame rate still need headset testing.

## See the Invisible

The ninth experience begins with remote sensing: collecting information from a distance. **Meet the sensors** reveals detailed conceptual 3D models of a Landsat-style satellite, a survey aircraft, and a camera drone above illustrative ground footprints. Selecting each compares the reach, timing, and detail of orbital, piloted, and local flights. The platform models and footprints are not to scale. **Explore light bands** introduces electromagnetic radiation (EMR), visible blue/green/red and invisible near infrared, and multispectral bands before **View Landsat scenes** opens one of three real, aligned natural/false-color image pairs: San Francisco Bay (Landsat 5, 1997), the Everglades and Miami (Landsat 5, 2011), or London (Landsat 7, 2002). The scene is chosen in shuffled order on each launch, without an immediate repeat. **Natural color** displays visible red/green/blue; **False color** assigns near infrared (NIR) to display red, visible red to green, and visible green to blue. **NDVI** displays an illustrative vegetation-index color ramp with an on-image legend. The selected view button is highlighted. Point and trigger on the image to compare displayed band brightnesses. **Takeaways** explains NIR and NDVI across all scenes.

The source composites are real Landsat-derived visualizations, not raw band data. The bars and vegetation-index preview use rendered JPEG display values, with preview colors stretched separately within each scene; the preview is **not measured NDVI** or a vegetation-health diagnosis. Scientific NDVI uses calibrated near-infrared and red reflectance: `(NIR − red) / (NIR + red)`. The terrain in NASA's oblique Bay rendering is exaggerated threefold. Development preview: `?preview&demo=spectral`.

## Where Did the Cluster Go?

The seventh experience uses 250 mapped Soho buildings, 40 mapped housing blocks, and eight pumps from GeoDa's digitizations of Snow's 1855 Broad Street map. The building and block datasets each total 489 recorded deaths **in these particular source files**, not every cholera death in the outbreak. **Buildings** shows the mapped points, with circle size representing death count, and the street corridors between blocks. **Plan A** groups adjacent whole blocks into six compact wards, placing 176 recorded deaths in one ward beside the Broad Street pump. **Plan B** groups the same blocks into six connected diagonal wards and splits nearby high-count blocks among them; its highest ward total is 94. **Plan C** uses six connected east–west wards, moving the darkest shading north of the pump. **Plan D** uses four broader connected wards whose totals all fall between 100 and 149, making the choropleth appear nearly uniform. These are deliberately contrasting hypothetical plans; every one preserves all 489 deaths. The selected plan is highlighted. Point at a colored block to outline its ward and read its death count just above the plan buttons. The fixed light-to-dark blue legend represents **recorded death counts per ward**, not mortality rates: broader wards cover more blocks, and no population denominator is available. Yellow marks the Broad Street pump and cyan marks the seven other mapped pumps in every view. Ward boundaries follow the gaps between the source blocks rather than a square grid. They are teaching examples, not historical wards or reconstructions of Monmonier's specific map panels. The source's separate building and block digitizations align approximately but do not place every building point inside its corresponding polygon, so ward totals come directly from the block dataset rather than a spatial join of the displayed points.

The **Takeaway** button opens a summary at any point, and the same screen appears after four minutes with **Restart** and **Exit to Menu**. The lesson is inspired by Mark Monmonier's Snow-map aggregation example in *How to Lie with Maps*. It explains how zoning and broader aggregation can disperse a street-level concentration in a shaded map; the modifiable areal unit problem (MAUP) concerns changes in mapped summaries caused by zone boundaries and scale. The lesson does not establish a statistically significant cluster or prove a causal source. Development preview: `?preview&demo=cluster`.

## Make the World Flat

The third experience displays a slowly rotating globe beside the same public-domain Natural Earth land outlines on a surface that unfolds into a flat map. Visitors can discover that holding a controller trigger on the globe spins or tilts it; vertical drag stays screen-consistent as the Pacific side comes into view, and a swipe coasts before the gentle default spin resumes. The visitor can choose **Plate Carrée** (equirectangular), **Mercator**, or **Cylindrical equal-area**; **Wrap/Flatten** animates the transformation. Dragging the flat map left or right moves the central meridian continuously; in equal-area mode the standard parallel can be switched between 0° and 30°. The equator and Prime Meridian are emphasized on both views. **Tissot circles** overlays equal-size small circles on the source globe and their projected shapes on the map. Six longitude columns are evenly spaced at 60° intervals, including the Pacific seam. A trigger tap on a circle highlights the same geographic circle on globe and map; tapping elsewhere clears the selection, while dragging the globe spins it. A small callout beside the selected circle reports its approximate local shape ratio and map area relative to the same-size ground circle at the equator; it follows a visible circle in the wrapped view too. The active projection button is highlighted. Roundness indicates local shape distortion and relative size indicates local area distortion. These finite 8°-radius symbols approximate the infinitesimal indicatrix. Each projection is fit with a uniform display scale to avoid adding artificial shape distortion. A readout compares each projection's local map-area scale at 60° N with the equator: approximately 2×, 4×, and 1×, respectively. The projection mesh has about 4,700 vertices and updates locally in the browser, so the interactive choices require no server or runtime download. The **Takeaway** button opens a dedicated summary of distortion and projection choices at any time; it also appears after four minutes with **Restart** and **Exit to Menu**. This is a teaching comparison of three cylindrical projections, not a general-purpose projection editor. Development preview: `?preview&demo=projection`; use the mouse to spin the globe, recenter the map, and select Tissot circles there.

The landmass experiment begins with Australia facing the visitor. Grip a landmass on the globe, then move its gold outline north or south over the flat map; grip the outline again to reposition it. A cyan outline marks its home latitude. The landmass is rotated on a virtual sphere before each projection, preserving ground distances and area. The tooltip compares the moved map footprint with the footprint at home latitude. Mercator enlarges high-latitude footprints; cylindrical equal-area keeps their map area while changing shape. Movement stops before any part of the landmass crosses the map's polar limit. A trigger click away clears the comparison and resumes the globe's spin. In development preview, mouse drag simulates the grip.

Each of these experiences starts its four-minute timer only after its introduction button is pressed. **X** restarts it, **Y** recenters the display, **A** opens the existing sound menu, and **B** returns to the twelve-demo gallery. On Quest, check gallery readability and targeting as well as the demos' frame rate and transitions.

## What Changed?

The eleventh experience uses five real Landsat pairs from NASA and USGS: the June 2007–June 2008 Illinois/Indiana flood, Yellowstone before and after the 1988 fires, North Dallas suburbs in August 1984 and August 2009, Mount St. Helens before and after the 1980 eruption, and Joplin before and after the May 2011 tornado. The same scene fills a floating image panel. Select **Slider** to drag the white divider, **Spotlight** to reveal the later image through a circular window that follows the controller ray, or **Head Tilt** to dissolve between dates by gently tilting left (before) or right (after). The mode buttons sit below the image, and comparison remains available after choosing an answer. The image and answer buttons share a plane. Choose an interpretation to reveal a brief explanation and the next place. Dotted outlines mark example areas in the Dallas, Mount St. Helens, and Joplin views; the widespread flood and fire changes have no outline. After the fifth case, **Show Takeaway** opens a summary of change detection, aligned images, matching season and bands, and corroborating records. **Restart** and **Exit to Menu** are visible there. The lesson also wraps up after four minutes. Development preview: `?preview&demo=change`.

The JPEGs are locally bundled crops or encodings of the NASA and USGS source images. The two frames in each case show the same area. Most cases use infrared false color; Dallas and Joplin use natural color. The lesson asks visitors to recognize visible patterns, while the short interpretation relies on the NASA or USGS event description. These rendered images are for visual interpretation rather than calibrated pixel-by-pixel change measurement. See SOURCES.md for dates, bands, image provenance, and reuse terms.

## Between the Rain Gauges

The fifth experience introduces **spatial interpolation** as estimating values between measured places, using 12 synthetic rainfall readings. Each post rises from a common plane to its measured value in millimeters. The visitor compares the readings alone, stepped nearest-station zones, a broad Gaussian-smoothed trend, and an exact inverse-distance-weighted (IDW) surface. All views share the same value color scale. The stepped surface assigns each location its nearest station's reading. On the smooth surface, short amber segments show readings above the trend and cyan segments show gaps up to a trend above the reading. Surfaces fade between modes.

A gold question mark marks an unmeasured location. The controller ray reaches the model's base plane, where a gold ring shows the point that will be selected; the ray and ring remain visible through raised surfaces. Point and press the trigger to move the question mark there. In IDW mode, gold station markers and lines identify its three nearest gauges. **Explain IDW** places value labels beside those gauges and shows their measured values and normalized inverse-distance-squared weights (power 2), followed by the estimated rainfall total. The calculation is recomputed as the visitor moves the question mark. One grip moves or rotates the model, and its stick snap-turns it 45°; two grips resize it; **Y** restores its starting pose. **Takeaway** summarizes spatial interpolation with Restart and Exit to Menu, and the same summary appears after four minutes. Development preview: `?preview&demo=interpolation`.

The values and station locations are original synthetic teaching data. Vertical height represents rainfall value, not ground elevation. The Gaussian trend is a deliberately smoothed kernel average; it is not presented as a spline. Nearest-station zones are a discrete assignment. The demo illustrates model assumptions, not a forecast or accuracy claim. See SOURCES.md for the IDW and spline-method distinction.

## Where Should It Go? (paused prototype)

This hidden prototype uses a purpose-built schematic town instead of the forested shared landscape. It has a river, floodplain, roads, 24 home groups, and three proposed clinic sites. Point at a site to drape a **450 m straight-line buffer** over the terrain; homes inside glow, and a readout gives the represented residents, road distance, and flood exposure. **Compare scores** reveals the floodplain and three animated score columns. **Reach first** weights nearby residents 72%, road proximity 20%, and flood safety 8%; **Flood safety first** weights them 30%, 10%, and 60%. The preferred site changes from riverside B to hill-road A. The score inputs share a 0–1 scale, and displayed scores are rounded to 0–100. One grip moves the model and its stick snap-turns it 45°; two grips resize it; **Y** restores its starting pose. **Takeaway** explains buffers, weighted overlay, and the role of priorities. Development preview: `?preview&demo=suitability`.

All places and resident counts are synthetic. The buffer and road-distance criterion use straight-line distance. This is a quick multicriteria lesson; actual clinic siting also needs travel networks, site feasibility, costs, and community input. The four-minute timer starts after the introduction.

## Scan the Hidden World

Choose the eighth experience in the shared menu, then select **Synthetic scan** or **Room scan · MR** from the two cards. The choice screen briefly explains that lidar (Light Detection and Ranging) times returning laser pulses to build a 3D point cloud. The synthetic scan opens an outlined miniature scene; hold the trigger and sweep a controller through it to collect a point cloud. It illustrates first-surface sampling without using a laser or measuring return time. One side grip moves/rotates the model; while a grip is held, that controller’s stick snaps the model 45° left, right, up, or down once per deflection. Both grips resize it (0.22–0.75, default 0.43). Rotate and scan another side to observe formerly blocked surfaces. **Reset View** restores the pose without discarding points.

Seven original procedural scenes rotate in shuffled order: **Woodland ruins**, **Ravine bridge**, **Hillside village**, **Terraced lookout**, **Forest survey**, **Covered courtyard**, and **Survey tower**. They demonstrate occlusion, under-deck and interior blind spots, canopy obstruction, elevation sampling, and narrow-feature point density. Starting or restarting the synthetic experience draws the next scene, with every scene appearing once per cycle and no immediate repeats across cycles. Restart begins another run with the next scene. Rotation is per app session; scenes never change during an active scan. **Clear scan** keeps the current scene. Real-room scanning is independent.

**Show scene** replaces the point cloud with a shaded, procedurally textured reference model of the same ground, structures, and trees; **Cloud only** returns to the samples. The model is a stylized scene, not a photographic reconstruction. A brief ray shows each central first-surface return, and newly acquired points brighten before settling into ground/structure/vegetation colors. **Hide plants** filters vegetation points, with **All points** restoring them. Filtering never changes what blocks a scan ray and never invents returns from unseen ground. Each scene presents a scan challenge and its own short takeaway connecting the observation to lidar survey concepts such as occlusion, overlapping viewpoints, point density, and digital elevation models. **Clear scan** discards observations during a run. The takeaway hides the model and scan, showing only the summary plus **Restart** and **Exit to Menu**. Each run wraps up after four minutes of visible session time.

This is a controller-driven illustration of first-surface range sampling. It does not use Quest room meshes, depth sensors, cameras, real lidar, multiple returns, or automated classification. Color/class labels come from known synthetic objects. Each sweep fires a small cone of rays; only the nearest hit is recorded. Samples are deduplicated in model coordinates and capped at 18,000. No scan leaves the device or persists after restart. Modeled scene positions and classifications are exact; real scanning also has measurement and positioning errors. See SOURCES.md for USGS background.

Development-only `?preview&demo=scan` provides front/back sampling actions through the same nearest-hit routine for repeatable visual review. Add `&scene=ruins`, `bridge`, `village`, `terraces`, `canopy`, `courtyard`, or `tower` to inspect a particular model. These controls are excluded from production; real controller sweeping still needs headset verification.

### Tripod field survey

The **Tripod survey** choice opens a walkable, full-scale version of the current synthetic scene. Grip the lidar tripod to carry it; the left stick still walks and the right stick still aims a teleport or snap-turns while it is held. Release the grip to set the scanner down, then trigger a scan. Each placement densely samples visible target faces, and four placements contribute to one cumulative coverage score. Scan stations must be at least 3 m apart in the synthetic scene; attempting a repeat position leaves the scan count unchanged and displays a move-tripod prompt on the clipboard. A different angle can reveal occluded surfaces. The generic terrestrial scanner has a rotating head, lens, leveling mount, telescoping tripod legs, and feet. The left-hand clipboard shows the growing miniature point cloud and remaining scans. After the first completed scan, trigger-drag the cloud or use **Rotate ◀/▶** to turn it without changing the survey; this remains available after every scan. **Takeaway** opens the result and explanation after the scans, with Restart and Exit to Menu. A trigger aimed at a clipboard button activates that button; a trigger on the point-cloud preview drags it and never spends a scan; a trigger aimed elsewhere starts a scan when the tripod is released. Development preview: `?preview&demo=scan&mode=station`. Point colors are assigned from known synthetic surface materials. The scene, point cloud, and coverage score are teaching models and need Quest locomotion and controller validation.

### Scan your room (experimental Quest 3S path)

From the VR scan choice screen, choose **Room scan · MR**. The app ends VR and requests a mixed reality session directly. If Quest requires a fresh user gesture, choose **Open room scan in MR** on the browser page. You can also launch the room scan from that page. Once in MR, choose **Start room scan**; **B** returns to a small MR menu and pressing **B** again exits MR. Use the browser's VR button to reopen the other experiences. Allow the browser's spatial permission if requested. Aim a controller at nearby physical surfaces; up to three green dots indicate actual WebXR hit-test returns in a short horizontal fan. Hold the trigger and sweep to accumulate a point cloud. This path requests the WebXR `hit-test` feature and default plane-type surface estimates. It does not claim access to raw live depth, a global mesh, photogrammetry, camera images, or semantic classification; the runtime determines which surfaces are represented and whether its data is reconstructed or updated live.

**Freeze** centers and scales a copy of the recorded points in front of you. Use one/two side grips to move/rotate/resize it. **Resume** restores the original recorded room coordinates. **Color** switches between relative height (low green to high yellow) and capture distance from the scanning controller (near blue to far red). The display names both ramp endpoints. **Clear** discards points; **Retry** retries source creation when surface access fails or no hits arrive. **Takeaways** opens the summary whenever the visitor is ready. Room registration is preserved during Reset View while live; only the controls move. Reset View restores the miniature when frozen.

No synthetic positions are substituted for missing real data. Unsupported API, rejected permission, and no-hit states are shown explicitly. Each tracked controller keeps a center hit-test source and requests two angled `offsetRay` sources. If the browser rejects either extra source, the center scan continues. Only returned poses become dots; the fan never fills in gaps by interpolation. Samples are deduplicated at 1.5 cm, restricted to 0.2–8 m range, and capped at 18,000. These limits are application choices, not sensor accuracy claims. Captures stay in memory and clear on restart, session exit, or reference-space reset. The visitor can open takeaways early; the four-minute wrap-up also freezes the cloud if it contains points. Keep passthrough visible; do not treat the cloud as a complete obstacle map.

Device acceptance is still required on Quest 3S: API availability, actual surface-return quality, permissions, registration stability, tracking recovery, and useful point density. Desktop checks use mocked API results and cannot establish those properties.

## Sound effects

Original Web Audio synthesis provides a quiet looping lounge melody on the in-headset menu, soft UI tones, distinct measurement/reveal/answer/layer/overflow/pixel cues, rate-limited pings for newly collected scan points (including room scans), and filtered water noise that begins with rain/pour input and fades shortly after release. Walking is silent on land and in water. Direct map picks, scan triggers, model grips, and projection interactions have light press feedback alongside the demo buttons. Press sounds follow the Effects control. Menu music fades out when a demo starts. Synthetic scan ping pitch varies slightly with return distance; it does not encode material. No sound files or external audio services are loaded. **A** on the right controller opens a small, world-anchored sound menu from the main menu or any demo. It controls master mute, 0–100% volume, menu music, nature ambience, and effects independently; A or **Close** dismisses it. The lesson timer and scene interactions pause while it is open. The active lesson visuals, including models, landscape, and clipboard, hide against a dark VR backdrop until the menu closes; controller rays and labels remain visible. Mixed-reality passthrough remains visible. Preferences are remembered locally when browser storage is available. Audio initializes on XR entry, fades out when the page/XR session is hidden, and remains optional if audio is unavailable. Quest loudness and comfort require headset listening.
